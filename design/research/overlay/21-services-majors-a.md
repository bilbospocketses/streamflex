**Correction to pass 1 (GitHub stability claims).** Pass 1 used `gh search repos`, which returns an empty list on this machine even when repos exist. Every "`gh search` returned no repos" line below is therefore void. The GitHub REST search (`gh api -X GET search/repositories -f q=...`) finds many active auto-skip and hotkey extensions for Disney+, Max and Hulu; see the Stability lines.

**Pass 2 headline findings.**
- Prime Video's keyboard shortcuts are now VERIFIED from Amazon's own help page. Disney+, Max and Hulu are still only REPORTED, but with several agreeing sources and, for Max and Disney+, extension source code.
- **Disney+, Max and Hulu do not have a full YouTube-style key set.** Max natively handles only F, Space/K/P, and Z/X (REPORTED); every Max hotkey extension exists to add the arrows. Hulu's arrows act only when the seek or volume bar has focus. Disney+ Space is flaky when the control bar is hidden. So the overlay should drive the `<video>` element directly for seek, volume and play/pause, and should not rely on the site's keys.
- Fullscreen from an extension is a trap: a content script's `requestFullscreen()` is refused when it is not triggered by a real user gesture, such as a command arriving from a remote or phone (extension author's changelog; a physical keypress handled by the page is a gesture, so a key-driven overlay may still work; untested). Use the extension's window-level fullscreen (`chrome.windows.update` / `browser.windows.update`), or the browser's own kiosk / F11 mode.
- All three Disney-family services (Disney+, Hulu, and ESPN) now share one "Disney+, ESPN, and Hulu Subscriber Agreement", last updated February 5, 2026, so the Hulu ToS and the Disney+ Subscriber Agreement are the same text.

## Netflix

1. **URLs.** Player `https://www.netflix.com/watch/<id>`; browse `https://www.netflix.com/browse`; sign-in `https://www.netflix.com/login`. (VERIFIED by long-standing structure; not re-fetched.)
2. **Support and quality.** Netflix's own table (https://help.netflix.com/en/node/23742, fetched 2026-09-28) lists Windows 10/11 with Chrome 117+, Edge 118+, Firefox 129+, Opera 92+; Mac Safari 14+ up to Ultra HD, other Mac browsers at most Full HD; Linux (Chrome, Firefox, Edge, Opera) supported "but cannot guarantee" and Customer Support does not troubleshoot Linux. VERIFIED.
   - Win Edge: yes; 2160p, HDR10 + Dolby Vision, 5.1/Atmos; PlayReady (carried, VERIFIED).
   - Win Chrome: yes; 2160p on Chrome 140+ (carried); no HDR, stereo (REPORTED, carried); Widevine, SL3000 path via PlayReady on newer builds (UNKNOWN default).
   - Win Firefox: yes; 1080p; no HDR; stereo (carried; Netflix table does not list 4K for Firefox). Widevine L3 / PlayReady CDM since Firefox 132 (carried).
   - Linux Firefox: yes (not blocked); table 1080p, practice 720p default (carried, REPORTED); no HDR; stereo; Widevine L3. No Linux block.
   - **Linux Chrome and Linux Edge (pass 3): named as supported on Netflix's own page, VERIFIED.** The Linux rows read (WebFetch of https://help.netflix.com/en/node/23742, 2026-09-28): "Chrome 117 or later - Up to Full HD (1080p)", "Edge 118 or later - Up to Full HD (1080p)" (Firefox 129+ and Opera 92+ likewise), with "Due to the many configurations of Linux, we can't guarantee Netflix will work on devices with a Linux OS and may have issues. Netflix Customer Support isn't able to help with troubleshooting devices with a Linux OS." So all three Linux browsers are listed, none blocked. **Practice is lower than the table:** Widevine L3 gives 720p in Chrome, Firefox and Opera on Linux (gHacks 2018-02-12, https://www.ghacks.net/2018/02/12/watch-netflix-in-1080p-on-linux-and-unsupported-browsers/; Linux Uprising 2018-07, both REPORTED and old). Linux Edge: no separate source; it is Chromium with Widevine, and 4K/1080p on Windows Edge comes from PlayReady, which is a Windows component (PK, REPORTED-level inference), so expect **720p, SDR, stereo** on Linux Edge too. Netflix's 720p cap on L3 is why the table's "1080p" is optimistic; treat 720p as the working number until measured.
3. **Account model.** Profiles with a web profile picker after sign-in (`/browse` redirects to `/ProfilesGate`); kids profile and profile PIN exist (REPORTED, background). Sign-in on web: email/phone + password, or a one-time sign-in code by email/SMS; passkeys UNKNOWN; no QR flow on the desktop web (REPORTED, background). "Extra member" model ($9.99) means separate logins (VERIFIED, plans page https://help.netflix.com/en/node/24926).
4. **UI technology.** React SPA on the web ("Akira") (REPORTED, background); no shadow DOM/canvas UI on browse; the player is a `<video>` plus React-drawn controls. Keyboard: rows use anchors and buttons, Tab reaches tiles, Enter opens; hover-expanded "billboard" tiles are mouse-driven (REPORTED, background). Netflix publishes no VPAT I could reach (UNKNOWN).
5. **Player.** Documented shortcuts: I could not fetch the shortcut help article (three guessed node URLs were unrelated). REPORTED (background): Space/Enter play-pause, F fullscreen, Esc exit, M mute, Up/Down volume, Left/Right seek 10s, S skip intro; Shift+Left/Right jumps. Skip Intro / Skip Recap are on-screen buttons; autoplay next episode with "Next Episode" countdown (setting-controlled). Subtitle and audio via the speech-bubble control in the control bar. Seek trap: programmatic `currentTime` seeks trigger error **M7375**; must go through Netflix's internal player API (carried, single-source gist).
6. **Stability.** Redesigns are incremental. Many extensions (Teleparty, Language Reactor, Netflix Party) exist and break on Netflix player changes several times a year (REPORTED, background). On GitHub, extension repos are mostly abandoned or Widevine-rip tools (`Puyodead1/wv-netflix-extension`, last push 2021-12-10; `Netflixyapp/netflixy-extension`, 67 stars, last push 2024-04-26, 14 open issues). No active large OSS tracker found via `gh search`. Anti-tamper: the Widevine/PlayReady path is untouched by extensions, but the player's own integrity checks fail on seek (M7375).
7. **ToS.** https://help.netflix.com/legal/termsofuse, "Last Updated: April 10, 2026" (VERIFIED, fetched). Quoted: "use any robot, spider, scraper or other automated means to access the Netflix service"; "use any data mining, data gathering or extraction method"; "circumvent, remove, alter, deactivate, degrade, block, obscure or thwart any of the content protections"; "insert any code or product or manipulate the content of the Netflix service in any way". The last is the closest to an overlay that injects DOM; it is aimed at code injected into the service. User-agent spoofing: not addressed in the clauses returned. Risk is account-level, not legal action, and no enforcement on remote-control extensions is known (UNKNOWN).
8. **Market weight.** Largest US SVOD; exact US subs not fetched (UNKNOWN). Prices US (VERIFIED, https://help.netflix.com/en/node/24926, 2026-09-28): Standard with Ads $8.99, Standard $19.99, Premium $26.99. The ad tier works in a desktop browser and is capped at 1080p (VERIFIED, page states 1080p for it).
9. **10-foot option.** None that is reachable from desktop. `netflix.com/tv` is not a public 10-foot UI (UNKNOWN; not fetched). The TV app is Gibbon, not web.
10. **Verdict.** Tier 1. Overlay difficulty medium. Biggest risk: the player breaks when driven by scripted seeks; drive the overlay with key events and the on-screen buttons, not `video.currentTime`.

## Cross-service notes

- **Disney-family ToS language is identical** in Disney ToU and Hulu ToS: the same "robot, spider, script, or other automated means" and the same "circumvent or disable any content protection system" sentences. Netflix and Apple add "manipulate" / "tamper" wording. None mentions browser extensions or user-agent spoofing (VERIFIED by what was returned; a summarizer read, so short clauses may be missed).
- **Firefox and Linux Firefox:** no source found showed HDR, 5.1 or Atmos for Firefox on any of the six services. **Linux Firefox (full build) is a user-chosen TARGET.** The measured or reported quality ceiling is a known limit to record and show, not a reason to defer the target. Current picture: Netflix 720p default, up to 1080p (REPORTED), Prime SD (VERIFIED), Disney+ 480p-720p (REPORTED), Max SD-720p (REPORTED, one 2026 source; a Linux block is possible and UNKNOWN, one occurred in 2020), Hulu likely 480p (inference from Firefox 480p plus Linux HDCP problems), Apple TV+ SD-720p estimate (UNKNOWN measurement). Cause in every case: desktop Linux Firefox only gets Widevine L3, so "SD, or, best case scenario, at 720p" (XDA, 2026-06-04, https://www.xda-developers.com/linux-finally-working-hdr-but-still-cant-use-it-most-streaming-services/). **This wording replaces the pass-1 sentence that said these findings "support the Linux Firefox is deferred position in SYNTHESIS 8a"; that was wrong given the user's decision. SYNTHESIS 8a should be corrected by whoever owns it.**
- **Linux Chrome and Linux Edge (added pass 3), all six services:** the three Linux browsers behave alike because the cap comes from Widevine L3, not the browser. Chromium Edge's higher quality on Windows comes from PlayReady, a Windows component, so Linux Edge should not exceed Linux Chrome (PK-level inference, no source shows Linux Edge quality for any of the six). Working ceilings, none blocked as far as known: Netflix 720p in practice (official table says 1080p for Chrome, Edge and Firefox; VERIFIED table, REPORTED practice); Prime SD; Disney+ about 480p (REPORTED); Hulu likely 480p (inference); Max and Apple TV+ SD to 720p (REPORTED / estimate). Only Netflix publishes an official Linux browser list (Chrome 117+, Edge 118+, Firefox 129+, Opera 92+, with a no-support-guarantee disclaimer); Hulu's list omits Linux; Disney+, Max, Prime and Apple lists were not readable. Whether Edge for Linux has an identical Widevine setup to Chrome for Linux was not confirmed by a source.
- **Key design consequences for the overlay (from this pass):** (1) Prime is the only one of the three with an official, global key set; (2) Disney+, Max and Hulu keys are partial or focus-based, so seek, volume and play/pause should be applied to the `<video>` element, as Stream Assistant does (`video.currentTime`, `video.play()`); (3) do not call `requestFullscreen()` from an extension content script (refused without a user gesture, per `Meowsbot/auto-skip` CHANGELOG 2.2.0); use window-level fullscreen or click the site's own control; (4) skip-intro and next-episode are on-screen buttons everywhere, with these anchors: Disney+ `.skip__button` / `[data-gv2elementkey="playNext"]`; Prime `.atvwebplayersdk-skipelement-button` / `.atvwebplayersdk-nextupcard-button`; Max `[data-testid="player-ux-skip-button"]` or class prefix `SkipButton-`; Hulu `.SkipButton` (low confidence); (5) Disney+ needs shadow-DOM piercing for ad state.
- **Still needed by hand:** the Netflix shortcut article; all six accessibility statements; per-service subscriber counts; a primary read of Hulu's, Disney+'s and Max's help-center shortcut pages (they are JS-rendered, so a real browser is needed, for example Playwright); the US-specific HBO Max terms (`/terms-of-use/en-us`, JS-rendered) and the US Prime Video Terms of Use; a measured (not reported) resolution on Linux Firefox for Hulu, Max and Apple TV+ on a real machine; whether the "S" key skips intros on Disney+.
